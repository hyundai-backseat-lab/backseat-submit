# 기능 명세 작성

입력: $ARGUMENTS

1. docs/strategy.md(목표·KPI·우선순위), docs/plan-proposal.md(기획서), docs/contest.md(심사 기준), docs/features.md(기존 항목), docs/domain.md(도메인 지식, 있으면)를 읽는다.
2. 항목 하나를 아래 형식으로 작성해 features.md에 [draft] 상태로 넣는다.
   - 완료 기준: 3~6개. 각 기준은 테스트나 화면·로그로 참/거짓을 판정할 수 있어야 한다("자연스럽게", "빠르게" 금지 → "300ms 안에", "로그에 X가 찍힌다").
   - 만들지 않을 것: 범위가 커지기 쉬운 지점을 먼저 막는다.
   - 시연 시나리오: verify-car가 그대로 따라 할 수 있는 단계(신호 → 기대 결과).
   - KPI: docs/strategy.md의 K1~K7 중 무엇을 얼마나 올리는지 한 줄(예: "K1 +1, K3 NaviHelper 추가"). 올리는 KPI가 없으면 기능으로 만들지 말자고 제안한다.
   - 폰 테스트: "이 기능을 폰 앱으로 똑같이 만들 수 있나?"에 대한 답과 이유 한 줄. "예"라면 차량 신호·경로를 어떻게 더 결합할지 함께 제안한다.
3. 판단이 필요한 지점은 선택지 2개와 추천안을 붙여 사람에게 한 번에 묻는다(질문은 최대 2개).
4. 사람이 승인하면 상태를 [approved]로 바꾼다. 승인 없이 [approved]로 바꾸지 않는다.
