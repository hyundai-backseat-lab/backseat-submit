## D-014 F-00 SDK 확인 결과와 골격 선택 (2026-11-05)
- Vehicle SDK는 2.3.2를 쓴다(2.3.1은 Pleos Maven에 없음). Pleos Maven은 인증 없이 열려 있어 CI에 secrets가 필요 없다.
- 속도는 SDK 어디에도 없다 → `speedKmh`는 Pleos 구현에서 "미지원", 주행 상태는 결정표의 "속도 없을 때" 규칙으로 판정한다. 비상등·주차 브레이크·경고는 계기판 경고등(Telltale)에서 읽는다.
- 차량 신호 인터페이스는 신호마다 Flow를 따로 두지 않고 `StateFlow<VehicleState>` 하나에 `Reading`(미지원/모름/값)으로 담는다. 이유: 안전 판정이 여러 신호를 한꺼번에 봐야 하고, Sim 덮어쓰기·화면·테스트가 한 값만 다루면 되어 PT 설명이 쉽다. 대안: 신호별 Flow 9개(판정 때 combine이 필요해 복잡).
- debug/release 차이는 소스셋별 같은 이름의 파일(`di/BuildTypeWiring.kt`)로 만든다. debug는 Pleos 구현을 `SimVehicleSignals`로 감싸고 release는 그대로 쓴다. 이유: release 빌드에 Sim 코드가 들어가지 않는다는 것을 manifest·APK로 확인할 수 있다. 대안: 런타임 `BuildConfig.DEBUG` 분기(코드가 release에도 남음). `SimReceiver`는 manifest에 선언하므로 `RECEIVER_EXPORTED` 동적 등록이 필요 없고 앱 프로세스가 죽어 있어도 `sim.sh`가 먹는다.
- detekt는 1.23.x가 Kotlin 2.2를 못 읽어 2.0.0-alpha.6(`dev.detekt`)을 쓴다. 규칙 이름이 바뀌어 `UnusedPrivateMember`→`UnusedPrivateFunction`·`UnusedPrivateProperty`, `UnusedImports`→`UnusedImport`로 설정했다. SDK 어댑터(`car/pleos`)는 함수 개수·일반 예외 규칙에서 제외한다. 알파 버전이므로 문제가 생기면 detekt만 교체한다.
- Kover는 safety·game·voice 패키지만 포함한다(포함 목록 방식이라 car/pleos·ui·debug·di는 자동 제외). 아직 이 패키지에 코드가 없어 `koverVerify`는 비어 있는 상태로 통과한다.
- compileSdk·targetSdk는 템플릿 값 37을 유지한다. CLAUDE.md의 "compileSdk 34"로 내려 보았으나 Compose Material3 1.4 등이 35 이상을 요구해 빌드되지 않았다. minSdk 28은 그대로. CLAUDE.md의 숫자는 사람이 고친다.
- `Gear`·`speedKmh`는 기준 3의 목록(방향지시등~속도)에 기어가 없지만, 속도가 없을 때의 주행 상태 판정(결정표 "속도 없을 때")이 기어에 기대므로 VehicleState에 둔다.

## D-017 STT 지연 측정 결과와 아이 차례 신호 방식 (2026-11-05)
결정자: 팀 결정.
측정(상세: docs/sdk-notes/Voice.md, 에뮬레이터 기준): STT `request()`→`ready`는 앱 시작 때 `initialize()`를 해 둔 상태에서 연속 5회 0.14~0.38초였다. `initialize()`를 요청 직전에 하면 약 0.4초가 더 들었다. TTS `done` 직후 0·300·1000ms 간격으로 request해도 최대 1.42초였다. 반면 앱 시작 직후 첫 차례(인사 TTS → 듣기)에서는 최대 5.6초가 관측됐다.
무엇을: (1) 앱 시작 시 STT `initialize()`를 미리 한다. (2) 아이 차례 신호(효과음 + "이제 말해!")는 STT `ready` 뒤에만 낸다. (3) 8초 무응답 타이머는 신호 뒤부터 센다. (4) 첫 차례의 큰 지연은 원인이 확인되지 않았으므로 F-15(PT 안정화)에서 다시 확인한다.
왜: `ready` 전에 말하면 앞부분이 인식되지 않을 수 있고, 신호가 `ready` 뒤에 나가면 아이가 말하는 시점과 마이크가 듣는 시점이 어긋나지 않는다. 미리 `initialize()`하면 약 0.4초가 준다.
대안: 신호를 `ready` 전에 내고 앞부분 손실을 감수하기(말이 잘림), TTS 재생 중에 `request()`를 걸기(앱 목소리를 아이 답으로 인식하는 반향 위험이 있어 테스트하지 않음), 큰 지연의 원인을 구현 전에 더 파기(이번 측정으로 재현되지 않아 보류).

## D-018 F-02 놀이 엔진 설계 (2026-11-05)
- `Round.answer()`는 판정(OK/DUP/NO_MATCH)과 다음 차례 준비를 함께 한다. 이유: 엔진은 "말하고, 듣고, 판정 결과에 따라 다시 묻거나 힌트"만 알면 되어 PT 설명이 쉽다. 대안: 판정과 전이를 나눈 두 메서드(엔진이 상태를 알아야 함).
- 앱 말은 한 문장, 거기에 신호("이제 말해!")를 더해 한 차례 2문장 이하(기준 6). 칭찬은 문장 앞에 쉼표로 붙인다("맞아, 사과는 달아"). 아이 차례 신호는 다시 말해줄래?·그건 아까 나왔어! 뒤에도 매번 낸다. 이유: 신호가 "지금 듣고 있다"를 뜻하게 일관되게 하려는 것이다.
- 실패 처리: 빈 결과·오류·엉뚱한 대답·반복은 한 번만 다시 받고 두 번째에서 힌트로 넘어간다. 아이 차례 신호 뒤 8초 무응답은 다시 묻지 않고 바로 힌트다(기준 3).
- 연상어 데이터는 단어 → 연상어 목록 하나로 형용사와 명사를 번갈아 잇는다(75개 단어, 249쌍, 모든 연상어가 다시 키로 있어 놀이가 막히지 않는다는 테스트가 있다). 다음에 이을 단어는 "아직 안 나온 첫 번째"로 정해 재현 가능하다. 대안: 무작위(테스트·시연 재현이 어려움).
- 신호 소리 섞임 판정은 공백·문장부호를 뺀 결과가 "이제말해"를 포함하거나, 3글자 이상이 신호의 일부일 때다. 한두 글자는 아이의 진짜 대답일 수 있어(예: "해") 무시하지 않는다.
- "한 차례"는 앱이 한 번 말하는 문장 + 아이 차례 신호다(2문장 이하). 힌트("사과 같은 말도 좋아요!")는 실패한 차례를 닫는 별도의 한 문장이고, 다음 차례의 앱 말과 이어 붙이지 않는다. 신호 소리가 섞인 대답에 아이 말이 같이 있으면("이제 말해 사과") 신호 부분만 빼고 아이 말을 쓴다.
- 효과음은 음원 파일 없이 ToneGenerator로 낸다(`car/android/ToneBeeper`). 대안: assets 음원(저작권·용량 관리가 필요).
- F-01 점검 코드(VoiceCheck, RecordingProbe)는 게임이 대신해서 지웠다. 녹음 코드가 필요해지면(F-08) PR #7의 기록에서 가져온다. 말잇기 자동 시작은 debug 전용(`RUN_GAME_ON_LAUNCH`)이다: 주행 중 권한 팝업·자동 발화 금지, 시작 화면은 다른 기능의 몫이다.
- 단위 테스트의 JSON 파싱을 위해 `org.json`(JVM)을 testImplementation으로만 추가했다(안드로이드 내장 org.json은 단위 테스트에서 동작하지 않음).

## D-021 설계서와 기존 문서의 충돌 정리 (2026-11-10)
결정자: 팀 결정. 적용: docs/features.md "공통 정책".

- 종료: 무음 종료(그만하기 확인 후·차량 경고·장애·화면 이탈·휴식 2분 초과)와 도착 마무리(F-05, 게임이 마무리 문장 후 Finished) 두 종류. "그만할까요?" 확인 질문은 종료 음성이 아니라 유지하고, 멈춤 중 종료 요청은 확인 없이 즉시 종료. 기존 F-04 종료 인사는 없앤다.
- 무응답: 미션 안 단계는 게임이 처리(NoAnswer SILENT·UNHEARD), 응답 없는 미션 3개 연속이면 휴식, 휴식 2분 초과 시 무음 종료. 이유: 설계서의 "무응답 → 휴식"과 기획안의 "3단계·3미션 후 종료"를 합치고, 휴식 중 마이크를 무기한 켜 두지 않기 위해서.
- 내비 안내: 1차는 오디오 포커스 상실·회복을 "다른 음성 안내" 멈춤 사유로 처리하고 자동 재개한다. 원인을 내비로 단정하지 않는다(설계서 5절). NaviHelper로 내비 안내를 구분하는 것은 F-14(11/12 이후).
- 설계서 보완: 차량 신호 멈춤은 SessionController의 멈춤 사유 집합으로(휴식은 별도 플래그), 결정표는 요구사항 정의서 '멈춤정책'으로 단순화(정차 중 방향지시등 = 멈춤), 와이퍼·문 열림 반응과 도착 처리 추가, 화면 이탈은 onStop 기준(화면 분할에서 내비 터치는 이탈 아님), ON_DEVICE 불가 시 서버 모드 자동 전환 금지(F-01 기준 5의 HYBRID 대안 삭제).
- 게임 계약 최소 확장: Answer(candidates), NoAnswer(reason), Arrived, GameMessage(text, cardId), GameNext.SuggestRest, createGame(gameId, PlaceSource).
- 하네스: PleosClient 인터페이스 하나는 Fake·Sim 자동 검증(D-006)을 위해 유지한다. 패키지 이름·check-docs.sh 금지 목록·Kover 포함 목록·CLAUDE.md·스킬의 경로는 코드를 옮기는 F-22에서 함께 바꾼다(문서만 먼저 바꾸면 check-docs.sh와 실제 코드가 어긋난다).
- 기본값(바꾸려면 팀 논의): 와이퍼 카드는 앱 화면이 보이면 이용 전에도 재생, 말잇기는 관찰 미션 3개마다 1판, 멈춤 중에도 제어 요청은 인식, 무응답 대기는 놀이 공통 14초.
- 대안: 앱 발화 중 제어를 1차에서 빼고 응답 차례에만 마이크를 여는 방식(반향 위험이 없고 구현이 단순하지만 설계서 범위를 충족하지 못해 제외).

## D-029 시작 요청과 화면 이탈 (2026-11-11)
결정자: 개발자 A. 적용: F-04, `SessionController.requestStart`, `MainViewModel`, `MainActivity.onStop`.
- 시작 조건(주차, 차량 경고 꺼짐, 마이크 권한, TTS·STT 초기화)은 세션이 판단하고 이유(StartBlock)를 돌려준다. 화면은 이유만 보여 준다. 경고가 켜진 채 시작하면 경고 신호가 바뀌지 않아 종료되지 않으므로 시작 조건에 넣었다.
- 권한 창을 띄운 시작 요청은 ViewModel이 기억하고, 그 사이 주차가 풀리면 지운다. 다시 주차해도 자동으로 시작하지 않는다(F-04-02).

- debug의 앱 실행 즉시 자동 시작(RUN_GAME_ON_LAUNCH)을 없앴다. 시작 조건을 우회하기 때문이다. 대신 `sim.sh start`가 버튼과 같은 길(requestStart)로 시작을 요청한다.
- 음성 장애(권한 상실·초기화 실패·언어·API 미지원)는 못 알아들음과 구분해 장애 종료한다. 코드 목록은 `TurnListener.kt`의 FATAL_CODES.
