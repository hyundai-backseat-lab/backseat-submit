## 공통 정책 (모든 음성 기능이 따르는 규칙)

### 주행 상태 판정
- 속도는 SDK에 없다(D-014). 주차 = 기어 P 또는 주차 브레이크 / 정차 = 기어 D·R + 브레이크 페달을 2초 이상 계속 밟음 / 주행 = 그 외 D·R. 저속은 속도 출처가 생기면 쓰고, 없으면 주행으로 본다.
- 값을 모르면(Reading.Unknown) 결정표에서는 "주행"(안전한 쪽), 시작 조건에서는 "주차 아님"으로 다룬다.

### 주행 상태 × 신호 결정표 (F-03의 기준)
| 신호 \ 상태 | 주차 | 정차 | 저속 | 주행 |
|---|---|---|---|---|
| 방향지시등 | 계속 | 멈춤 | 멈춤 | 멈춤 |
| 브레이크 페달 | 계속 | 계속 | 계속 | 멈춤 |
| 비상등 | 멈춤 | 멈춤 | 멈춤 | 멈춤 |
| 다른 음성 안내(오디오 포커스 상실) | 멈춤 | 멈춤 | 멈춤 | 멈춤 |
| 차량 경고 | 무음 종료 | 무음 종료 | 무음 종료 | 무음 종료 |
| 목적지 도착 | 도착 마무리 | 도착 마무리 | 도착 마무리 | 도착 마무리 |
- 좌우 방향지시등 동시 = 비상등. 정차 중 방향지시등의 "짧은 발화만(3초)" 규칙은 멈춤으로 단순화했다(D-021).
- 브레이크는 주행 중에만 멈춤 신호로 쓴다. 정체 구간 브레이크에서는 놀이를 끊지 않는다(D-010).
- 멈춤 = 300ms 안에 앱 발화(TTS·효과음·목소리 카드) 정지, 일반 응답 접수와 무응답 판정 정지. 제어 요청(아래 "음성 제어")은 계속 받는다.
- 재개 = 모든 멈춤 사유가 풀리고 1초 뒤. 말하던 중이었으면 끊긴 문장만 다시, 듣던 중이었으면 말없이 듣기만 다시. 미션을 처음부터 다시 설명하지 않는다.
- 오디오 포커스 상실은 원인을 단정하지 않고 "다른 음성 안내" 사유로 기록한다(설계서 5절: 포커스 상실만으로 내비라고 단정하지 않음). 화면 문구는 "안내가 끝나면 이어서 해요". 포커스를 돌려받으면 다른 사유와 같은 규칙으로 재개한다(D-021).

### 멈춤과 휴식은 따로 보관 (설계서 4절)
- 멈춤 사유(차량 신호·다른 음성 안내)는 집합으로, 휴식은 별도 플래그로 보관한다.
- 휴식 진입: 사용자 요청("잠깐 쉬자"), 주차 중 일시정지 버튼, 응답 없는 미션 3개 연속(게임이 SuggestRest 반환). 휴식 전환은 짧게 알린다(멈춤 중이면 화면에만 표시하고 나중에 말하지 않는다).
- 휴식 재개: 명시적인 재개 요청("다시 하자", "계속", "이어서")만. 멈춤 사유가 풀려도 휴식은 유지된다.
- 휴식이 2분을 넘으면 무음 종료한다(마이크를 무기한 켜 두지 않기 위해, D-021).
- 멈춤 중 휴식 요청 → 휴식을 기록하고 멈춤이 풀려도 자동 재개하지 않는다. 멈춤 중 종료 요청 → 즉시 종료(확인 질문 없음). 멈춤 중 재개·재안내 요청 → 저장·예약하지 않는다(설계서 1절, 공통 이용 요구사항 4절의 "보류한 재개 요청"보다 우선).
- 휴식 중 재안내 요청 → 재개·종료 방법을 안내한다. 재안내만으로 재개하지 않는다.

### 음성 제어 (공통 명령, SessionController가 처리)
| 명령 | 인식 문구(정해진 표현부터) | 동작 |
|---|---|---|
| 재안내 | 다시 말해 줘, 뭐라고 했어, 다시 설명해 줘 | 현재 안내 다시. 휴식 중이면 재개·종료 방법 안내 |
| 휴식 | 잠깐 쉬자, 쉬고 싶어 | 휴식 진입 |
| 재개 | 다시 하자, 계속, 이어서 | 휴식 해제 |
| 종료 | 그만할래, 그만하자, 안 할래, 끝낼래, 그만(단독), 끝(단독) | "그만할까요?" 확인 → "아니"면 계속, 그 외·무응답(9초)이면 마무리 인사("오늘도 대단해요! n개 맞췄어요! 다음에 또 같이 놀아요!", 0개면 "다음에 또 같이 놀아요!"만) 뒤 종료(D-036). 멈춤 중이면 확인 없이 즉시 종료 |
- 문장 속 "그만"("엄마 그만 좀 해")은 무시한다.
- 인식문에서 제어 요청을 먼저 판별한다. 제어가 아니면 현재 열린 응답 차례일 때만 일반 응답으로 접수한다.
- 앱이 말하는 중에도 제어 요청을 받는다(설계서 5절, D-021). 앱 자신의 음성은 사용자 입력으로 처리하지 않는다(F-23).
- 힌트·다른 미션·난이도 변경 같은 게임 명령은 일반 응답으로 게임에 넘기고 게임이 해석한다.

### 종료는 두 종류 (D-021)
- 무음 종료: 차량 경고, 휴식 2분 초과, 음성 기능 장애(권한 상실·서비스 불가), 실제 화면 이탈. 이용을 먼저 종료 상태로 바꾸고 음성·대기 작업을 취소한다. 종료 음성은 없다(설계서 1절). 단 아이가 그만하기를 확인한 경우만 마무리 인사를 한다(D-036).
- 도착 마무리(F-05, 목적지 자동 감지): 게임이 마무리 문장을 마지막 계획으로 돌려주고 Finished. 멈춤 중이면 말없이 종료.
- 종료 후 화면은 결과(SC-07, 주차 중), 주행 중에는 "결과는 주차하면 볼 수 있어요". 새 이용은 주차 중 새 시작 요청으로 처음부터.

### 무응답과 못 알아들음 (D-021)
- 응답 차례는 STT ready 뒤에 아이 차례 신호(효과음 + 짧은 신호 문구)를 내고 연다(D-017). 무응답 대기는 신호 뒤부터 14초.
- 미션 안의 단계는 게임이 처리한다. 앱은 14초 무응답이면 NoAnswer(SILENT), 빈 결과·오류면 NoAnswer(UNHEARD)를 게임에 전달한다.
- 게임 단계: 무응답 1번째 말 걸지 않고 기다림 → 2번째 부드러운 안내 1회 → 3번째 다음 미션. 못 알아들음 1회 다시 묻기 → 또 실패하면 힌트 → 그다음 다른 미션.
- 응답 없는 미션 3개 연속 → 게임이 SuggestRest → 휴식 → 2분 뒤 무음 종료.
- 개별 발화를 못 알아들은 것과 음성 기능 장애를 구분한다. 장애는 무음 종료. 다른 음성 안내 때문에 잠시 출력이 끊긴 것은 장애가 아니다.

### 게임 연결 계약 (설계서 3절 + 최소 확장, D-021)
```kotlin
interface GameSession {
    suspend fun step(input: GameInput): GamePlan
    suspend fun close()
}
sealed interface GameInput {
    data object Start : GameInput
    data class Answer(val turnId: String, val candidates: List<String>) : GameInput // 인식 후보 여러 개
    data class NoAnswer(val turnId: String, val reason: NoAnswerReason) : GameInput  // 14초 무응답·빈 결과
    data object Arrived : GameInput                                                  // 도착 마무리
}
enum class NoAnswerReason { SILENT, UNHEARD }
data class GameMessage(val text: String, val cardId: String? = null) // 목소리 카드가 있으면 TTS 대신 재생
data class GamePlan(val messages: List<GameMessage>, val next: GameNext)
sealed interface GameNext {
    data class AwaitAnswer(val turnId: String, val prompt: String) : GameNext
    data object SuggestRest : GameNext
    data object Finished : GameNext
}
fun createGame(gameId: String, places: PlaceSource): GameSession
```
- 게임은 마이크·TTS·차량 SDK·PleosClient를 직접 쓰지 않는다. 장소 데이터는 PlaceSource로 주입받는다.
- 게임 안의 오류(장소 조회 실패 등)는 게임 안에서 데이터 없는 미션으로 대체한다. step이 예외를 던지면 앱은 재시도하지 않고 이용을 종료한다(설계서 6절).

### 말투 (요구사항 정의서 F-18)
- 앱 발화는 친근한 존댓말(해요체), 한 번에 1~2문장, 질문은 하나. 아이 목소리 카드는 아이 말투 그대로.
- "틀렸", "오답", "실패" 금지. 같은 문장·같은 시작 표현 연속 금지.

## F-00 프로젝트 골격과 차량 신호 연결 [done]
완료 기준
1. Pleos Maven과 Vehicle SDK 의존성이 추가되어 `./gradlew assembleDebug`가 로컬과 GitHub Actions 모두에서 성공한다(Actions에서 Pleos Maven 인증이 필요하면 [blocked] 후 사람에게 secrets 요청).
2. 품질 도구 설정: ktlint(코드 모양), detekt(안 쓰는 코드·복잡도, 기본 규칙 + `UnusedPrivateMember`·`UnusedImports` 오류 처리), Android Lint(`UnusedResources` 오류 처리), Kover(커버리지: safety·game·voice 패키지 라인 80% 미만이면 koverVerify 실패, car/pleos·ui·debug·di 제외). `./scripts/check.sh`가 ktlintCheck·detekt·단위 테스트를 돌려 PASS. `.editorconfig`에 `ktlint_function_naming_ignore_when_annotated_with=Composable`. 테스트 실패 시 이름·원인이 출력되도록 `testLogging { events("failed"); exceptionFormat = FULL }`.
3. `car/` 패키지에 `VehicleSignals` 인터페이스(방향지시등, 비상등, 브레이크 페달, 주차 브레이크, 경고, 와이퍼, 문, 속도를 Flow로 제공)와 Pleos 구현, Fake 구현이 있다. 지원하지 않는 항목은 Capability로 확인해 "미지원"으로 표시한다.
4. debug 빌드 구조는 "Pleos 구현 + Sim 덮어쓰기": `SimReceiver`(debug 소스셋, exported, `RECEIVER_EXPORTED`)가 `./scripts/sim.sh brake-on` 등을 받으면 해당 값만 덮어쓰고 로그 `Backseat SIM brake=ON`. release 빌드에는 포함되지 않는다.
